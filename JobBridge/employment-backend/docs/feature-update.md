# 새 기능 적용 및 검증 안내
기존 변수·객체·테이블 필드 이름은 유지했습니다. 신규 기능은 일반 SQL 업무 테이블 4개를 사용합니다. 자동 DB 초기화 기본값은 계속 never입니다. 기존 DB와 원본 ZIP, 스프레드시트는 변경하지 않았습니다.

## 테이블 누락 오류
Table 'employment_db.application_assessments' doesn't exist는 기존 DB에 새 업무 테이블이 적용되지 않았다는 뜻입니다.
기존 DB 자동 초기화 기본값은 never이므로 전체 스키마 자동 적용으로 바꾸지 않습니다.
새 feature-setup 프로필은 db/feature-tables.sql만 실행하여 누락 테이블을 생성합니다.
IntelliJ 실행 구성의 Active profiles에 feature-setup을 한 번 추가합니다. 기존 dev가 있다면 dev,feature-setup으로 지정합니다.
DB_URL이 의도한 개발 DB인지 확인하고 백업한 뒤 실행합니다. 정상 시작 후 프로필에서 feature-setup을 제거합니다.
이 프로필은 기존 행/열/테이블 이름을 바꾸거나 데이터 및 테스트 계정을 추가하지 않습니다.
이력서 기본 테이블 이름은 계속 resumes입니다.
프로필을 사용하지 않을 경우 SQL 콘솔에서 db/feature-tables.sql만 직접 실행해도 됩니다.
스키마가 누락된 경우 시작 단계에서 누락 테이블과 적용 방법을 안내하며, 반복 예약 작업 SQL 오류가 발생하기 전에 중단합니다.

## 기존 MariaDB에 적용할 때
실행 전에 반드시 백업하고 대상 DB를 확인합니다. UTF-8(utf8mb4) DB를 사용합니다.
1. db/feature-tables.sql: resume_files, resume_assessments, job_assessment_settings, application_assessments 생성.
2. db/enable-repeat-applications-mariadb.sql: 기존 applications의 공고·구직자 전체 기간 유일 인덱스를 일반 조회 인덱스로 바꿉니다. 진행 중 중복지원은 서비스에서 공고 행 잠금과 상태 검사로 차단합니다. 이 스크립트는 명시적으로 실행해야 하며 자동 실행되지 않습니다.
신규 빈 DB는 db/schema.sql과 db/reference-data.sql로 초기화합니다. 기존 DB에 전체 스키마를 재적용하여 업그레이드하지 않습니다.

## 동작
- 포트폴리오 파일 1개, PDF 최대 5MB. 확장자·파일 헤더·크기·소유권 검증, 인증 다운로드 및 no-store/nosniff. 별도 악성코드 검사 서비스는 연결하지 않았습니다.
- 교체·제거 후에도 지원 당시 첨부파일 버전을 보존합니다. 기존 링크 데이터는 지우지 않으며 신규 작성 폼은 파일 첨부를 사용합니다.
- 예시 직무기초 문항 10개, 서버 채점 0~100점. 문항 응답 API에는 정답을 포함하지 않습니다. 실제 인적성 진단이나 검증된 채용 평가도구가 아닙니다.
- 기업만 검토 기준 0~100을 설정·조회합니다. 공개 공고와 구직자 지원 응답에는 기준 점수를 포함하지 않습니다.
- 지원 당시 검사 점수·기준을 보존합니다. 최초 기업 상세 열람부터 48시간을 계산하며 재열람으로 연장되지 않습니다.
- 기준 미달 건은 48시간 후 담당자 검토 표시 및 1회 알림. 자동 불합격 결정은 하지 않습니다. 알림 작업 주기는 60초이며, 서버 재시작 후 다음 주기에 DB의 경과 건을 다시 확인합니다.
- 상위 10명을 별도 표시하고 전체 지원자 조회는 유지합니다. 동점은 지원 접수 순입니다.
- 진행 중 상태(APPLIED/UNDER_REVIEW/DOCUMENT_PASSED/INTERVIEW)에서는 같은 공고에 중복 지원할 수 없습니다. 결과 확정 또는 취소 후 새 지원은 별도 ID와 스냅샷으로 저장합니다.
- 답변 완료 문의는 작성자도 삭제할 수 없습니다. 행 잠금으로 답변 등록과 삭제의 경합을 막습니다.
- 목록은 12개씩 표시하고 13번째부터 다음 페이지가 생깁니다.
- 배너는 마우스 hover로 멈추지 않습니다. 키보드 포커스, 명시적 일시정지, OS의 동작 줄이기 설정은 유지합니다.
- 검색어·지역·고용형태·경력·정렬은 서로 유지하며 검색/필터 변경 시 페이지 번호만 0으로 돌아갑니다.
- 인증 문구 옆에 남은 인증 시간과 재전송 대기 시간을 표시합니다. 실제 SMS로 검증하지 않습니다.

## 제한
8번 사용자별 예시 데이터 생성은 사용자의 후속 요청으로 작업 범위에서 제외했습니다. 해당 생성기 코드는 추가하지 않았습니다. 테스트 내 격리된 계정·이력서·지원서 생성으로 소유권 분리는 검증합니다.
비밀번호 재설정은 기존 미제공 상태를 유지합니다. 커밋·푸시하지 않습니다.

## 최종 검증 (2026-10-23)
- H2: 73건 중 72건 통과, MariaDB 전용 1건 제외.
- MariaDB 10.11.18: 73건 모두 통과. JVM Asia/Seoul / 세션 UTC / UTF-8 신규 임시 DB. H2 보조 검사를 포함한 테스트 스위트 수입니다.
- 프론트엔드 페이지/순위 회귀 테스트 4건, lint, build 모두 통과.
- 기존 유일 인덱스 수동 전환 SQL은 별도 임시 테이블에 2회 적용하여 재실행을 확인.
- 실제 화면: PDF 첨부 저장 및 재조회, 예시 검사 답안 입력→서버 100점 채점, 지원창 단독 표시, 지원 제출, 새로고침 후 중복지원 차단 문구, 검색어·지역·고용형태·경력·정렬 유지, 기업 기준점수 70 저장·재조회, 점수 순위와 전체 목록 동시 표시 확인.
- 실제 화면: 로컬 SMS 모의 발송에서 전송/재전송 후 3분·60초 초기화 및 시간 만료 안내 확인. 실제 SMS 전송 없음.
- 실제 화면: 배너의 비버튼 영역에 포인터를 유지한 상태에서 2번→3번 슬라이드 자동 전환 확인.
- 48시간 경과는 DB 시각을 이용한 회귀 테스트로 검증했으며 실제 48시간 대기나 장시간 운영 시험은 하지 않음.
- 최초 임시 DB는 latin1 문자셋 때문에 한글 초기 데이터 오류가 발생했으며 UTF-8 새 DB에서 해결. 재사용한 테스트 DB에서는 고정 테스트 전화번호가 충돌하여 최종 검사는 새로운 빈 DB에서 실행함.
- 실행 클래스패스에 해당 DB 이력 프레임워크 JAR 없음, 소스에 관련 패키지/디렉터리 없음, 임시 MariaDB 내 관련 이력 테이블 0개. 신규 업무 테이블 포함 총 25개.
- 운영 DB, 실제 SMS/이메일, 다른 DB/JDBC/브라우저 조합, 악성 PDF 분석 서비스, 장시간 부하는 미검증.
