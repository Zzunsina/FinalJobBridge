# 취업연계 추천·응답 흐름

## 기존 DB 적용

서비스 DB에 `src/main/resources/db/employment-referral-upgrade.sql`을 한 번 실행하고 백엔드를 재시작합니다.
희망 조건 신청 기능은 `src/main/resources/db/employment-preferences-upgrade.sql`도 한 번 적용합니다.
사용자 면접 참여와 일정 조율 기능은 `src/main/resources/db/employment-coordination-upgrade.sql`을 한 번 적용합니다.
기업이 구체적인 면접 일정을 제안하고 사용자가 수락하는 기능은 `src/main/resources/db/employment-proposal-upgrade.sql`을 한 번 적용합니다.
새 설치 SQL은 제안별 이력을 저장하는 테이블만 추가합니다. 기존 제안이 없는 추천은 기업에서 새 면접 제안을 작성해야 합니다.
희망 업종·선호 직업 저장 테이블을 추가하고 기존 상담 상태를 기업 매칭 상태로 전환합니다.
기존 신청은 삭제하지 않으며 희망 조건이 없으면 ‘기존 신청 · 미입력’으로 표시합니다.
SQL은 `employment_referrals` 테이블만 추가하고 기존 신청, 기업 검토 의견, 이력서와 일반 지원서는 변경하지 않습니다.
대신 기존 실행 프로필에 `employment-referral-setup`을 한 번 추가해 시작한 뒤 제거할 수도 있습니다.
신규 빈 DB와 테스트 DB는 schema.sql에서 생성합니다.

기존 기업 지정 내역은 자동으로 추천 전달한 것으로 간주하지 않습니다.
관리자가 저장된 기업·공고를 확인하고 ‘저장된 기업에 추천 전달’을 눌러야 기업에 노출됩니다.
이전 방식의 기업 의견은 관리자 이력 화면에 별도로 보존합니다.
이전 방식으로 면접 단계가 된 건은 ‘현재 추천 종료 · 재매칭 시작’으로 새 흐름을 시작할 수 있습니다.

## 진행 순서

1. 사용자는 공개 이력서와 희망 업종·선호 직업을 제출해야 신청할 수 있습니다.
2. 관리자는 제출된 희망 조건을 확인하고 담당자·기업·공고를 저장합니다. 별도의 상담 단계는 없으며 신청 접수에서 기업 매칭으로 진행합니다. 지정만 한 정보는 기업·사용자에게 노출하지 않습니다.
3. 관리자가 ‘추천 전달’을 누르면 공개 이력서를 JSON으로 보관하고 기업과 사용자에게 알립니다. 전달 후 수정된 이력서는 추천 당시 내용에 영향을 주지 않습니다.
4. 기업은 면접 일시·방식·장소 또는 온라인 접속 URL·구직자 면접 안내를 작성해 제안합니다. 진행이 어려우면 사유를 전달합니다.
5. 사용자는 제안된 내용을 확인하고 수락 / 일정 변경 요청 / 참여 어려움을 선택합니다. 수락 시 자동으로 면접이 확정되며, 관리자는 일시나 장소를 작성·수정하지 않습니다. 변경 요청 시 기업이 새 제안을 작성하고 사용자가 새 제안에 응답합니다. 이전 제안은 보존하며 재제안 후에는 이전 제안을 수락할 수 없습니다. 참여 어려움은 해당 추천만 종료하고 재매칭으로 돌아갑니다.
6. 기업은 면접 단계에서 ‘채용 희망’ 또는 ‘진행 어려움’을 전달합니다.
7. 기업이 면접 후 채용 희망을 전달하면 ‘최종 합격·입사 대기’로 표시합니다. 기업이 첫 출근 일시·장소·준비물·연락처·추가 안내를 등록하고 사용자가 입사 안내를 확인합니다. 입사 예정 일시가 지난 뒤 사용자가 실제 출근을 확인해야 취업 완료가 됩니다. 관리자 목록은 10초마다 상태를 갱신합니다.

입사 안내/확인 기능은 `db/employment-onboarding-upgrade.sql`을 한 번 적용하고 백엔드를 재시작합니다.
이 SQL은 새 테이블을 추가하고 기존에 기업 채용 희망만으로 완료 처리한 건을 입사 확인 대기로 돌립니다. 실제 입사 확인 기록이 있는 건은 유지합니다.
사용자 완료 화면은 결과 요약과 입사 안내를 먼저 표시하고 면접 제안은 접힌 전형 이력으로 보관합니다.
‘입사하지 않음’은 사유를 받아 추천을 종료하고 재매칭하며, ‘도움 요청’은 관리자 문의로 접수합니다. 기존 추천/제안 이력은 삭제하지 않습니다.

‘진행 어려움’은 해당 추천만 종료하고 전체 취업연계는 기업 매칭 상태로 돌아갑니다.
관리자는 다른 기업·공고를 지정해 다시 추천할 수 있습니다. 추천 회차마다 이력서와 응답을 별도로 보관하며 같은 기업에 다시 전달하는 경우도 구분합니다.
기업·공고 변경이 필요한 진행 중 추천은 먼저 재매칭을 시작해야 합니다.
기업 면접 안내는 제안별로 보관하며 관리자 취업연계 안내(추천·재매칭 안내)와 구분합니다.
과거 추천은 조회만 가능하고 종료된 추천이나 다른 기업의 추천에는 응답할 수 없습니다.
동일 응답의 재시도는 추가 알림을 생성하지 않습니다.
