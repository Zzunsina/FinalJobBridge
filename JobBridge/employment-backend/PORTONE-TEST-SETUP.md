# 잡브릿지 · 포트원 V1 KG이니시스 테스트 결제

기업 `/company/advertising`, 관리자 `/admin/advertising`에서 사용합니다.
기존 기업·관리자 광고 화면과 DB는 유지하고 결제 연동만 V1으로 변경했습니다.

## 필요한 값 4개

`employment-backend/.env.local`에 다음 값을 넣고 백엔드를 다시 시작합니다.

```properties
PORTONE_IMP_CODE=imp고객사식별코드
PORTONE_CHANNEL_KEY=기존_KG이니시스_V1_테스트_채널키
PORTONE_API_KEY=V1_REST_API_Key
PORTONE_API_SECRET=V1_REST_API_Secret
```

- **고객사 식별코드**: 포트원 콘솔 → 연동 정보 → 식별코드·API Keys → **V1 API**. `imp`로 시작하는 값입니다. V2 Store ID가 아닙니다.
- **채널 키**: 기존 KG이니시스 `html5_inicis` **V1 테스트 채널**의 채널 키입니다. 실연동 채널을 넣지 마세요.
- **REST API Key·Secret**: 같은 상점의 **V1 API** 화면에서 확인한 값입니다. 이니시스 MID·signkey·INIAPI Key와 다른 값입니다.
- V2 API Secret이나 V2 테스트 채널을 새로 발급할 필요가 없습니다.
- API Key·Secret은 서버 전용입니다. 프런트엔드 환경변수·Git·채팅에 넣지 마세요.
- 기존 `.env.local`의 값은 자동으로 덮어쓰지 않았습니다. `PORTONE_API_SECRET`에는 반드시 **V1 REST API Secret**을 넣으세요.
- 이전 V2용 `PORTONE_STORE_ID`, `PORTONE_WEBHOOK_SECRET`은 이제 사용하지 않습니다.
- 키가 없어도 광고 심사 신청과 관리자 승인은 가능합니다. 승인된 신청 건의 결제 버튼만 준비 중으로 비활성화됩니다.

## KG이니시스 콘솔 설정과의 차이

KG이니시스 MID·웹결제 signkey 등은 **포트원 채널 설정 화면**에 등록하는 PG 정보입니다. 잡브릿지 소스에는 넣지 않습니다.
정상 등록된 기존 V1 테스트 채널을 그대로 사용할 수 있습니다.

## 결제 알림 (웹훅)

포트원 콘솔의 **V1 결제알림(Webhook)**에 아래 주소를 등록합니다.

`https://공개된-테스트-백엔드/api/payments/portone/webhook`

포트원 서버에서 로컬 `localhost`로는 접근할 수 없습니다. 본인 공개 테스트 서버나 관리하는 터널이 있을 때 등록하세요.
V1 알림은 `merchant_uid`, `imp_uid`, `status` 형식입니다. 이 구현은 알림의 `status`를 신뢰하지 않고 서버의 V1 인증키로 실제 결제를 다시 조회합니다. V2 웹훅 서명 시크릿은 사용하지 않습니다.
모르는 주문은 무시하고, 잘못된 형식과 과도한 요청은 차단합니다. 웹훅 등록 전에도 브라우저 콜백과 내역의 **결제 확인** 버튼으로 결과를 확인할 수 있습니다.

## 처리 흐름

1. 기업이 상품·이미지·공고·희망 기간을 입력하고 **광고 심사 신청**을 누릅니다. 이 단계에서는 결제창이나 결제 API를 호출하지 않습니다.
2. 관리자가 심사 대기 신청을 검토해 승인하거나 사유와 함께 보완을 요청합니다. 승인할 때 미결제 승인 건도 노출 자리에 포함하여 중복 판매를 방지합니다.
3. 승인된 신청 건만 기업 화면에 **결제 대기**로 표시되고 같은 신청 건의 **결제하기** 버튼을 사용할 수 있습니다.
4. V1 SDK로 결제창을 열었다 닫거나 다시 시도해도 주문번호와 신청 건수는 유지됩니다.
5. 서버가 V1 토큰으로 결제 금액·주문번호·테스트 여부를 재검증합니다. 결제 완료는 기존 승인 상태를 유지하며 지정한 기간에만 노출합니다. 결제 콜백이나 웹훅으로 심사를 자동 승인하지 않습니다.
6. 승인 전에는 결제할 수 없습니다. 미결제 신청은 기업이 철회할 수 있으며 보완 제출 시 이미지·희망 시작일을 갱신할 수 있습니다.
7. 노출 시작일이 지난 미결제 신청은 결제할 수 없습니다. 철회 후 새 기간으로 신청합니다.
8. 결제 후 환불은 V1 취소 API와 재조회로 확인합니다. 시연 결제는 실제 PG API를 호출하지 않습니다.

관리자 메뉴는 광고 신청 심사·결제/환불·상품 설정으로 구성합니다. 일반 목록의 ‘결제 미완료 내역’ 탭은 제거했습니다. 이전 방식에서 결제창만 열어 만들어진 임시 주문은 ABANDONED로 보존하되 일반 목록에서 제외합니다. 기존 정상 결제·시연 광고 60건은 유지합니다.

광고 이미지는 DB에 저장됩니다. 기업 광고는 홈 상단 슬라이드에 노출하지 않습니다. 홈 채용 카드 영역의 프리미엄 9개·스탠다드 21개·베이직 개수 제한 없음이며, 기간 중 승인 가능 자리를 확인합니다. 기존 광고 심사·보완·기간·환불 정책은 유지됩니다.

## 테스트 범위와 주의점

자동 테스트는 대체 응답 및 로컬 API 서버로 V1 토큰·조회·취소 요청, 테스트 모드·금액 검증, 웹훅 재조회, 브라우저 콜백·모바일 파라미터, 광고 심사·권한·환불을 검증합니다.
본인 테스트 키 설정 전에는 실제 KG이니시스 결제창에서 승인·취소를 확인한 상태가 아닙니다.
테스트 채널에서도 카드에 일시 승인 또는 출금이 발생할 수 있으니 포트원·KG이니시스의 해당 테스트 안내를 확인하고 진행하세요. 실연동 채널을 잘못 넣으면 실제 청구가 발생할 수 있습니다. 서버 검증은 실결제를 광고 결제로 인정하지 않지만 결제창에서 이미 발생한 청구를 자동 방지하는 기능은 아닙니다.
