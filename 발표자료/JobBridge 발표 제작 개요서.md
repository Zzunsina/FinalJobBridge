# JobBridge 발표 자료 제작 개요서

## 제작 요청

이 개요서와 첨부 자료를 바탕으로 JobBridge 프로젝트 발표용 PowerPoint(.pptx)를 작성해 주세요. 발표 본문은 시연을 포함해 약 8~10장으로 구성하고, DB 명세서는 뒤에 부록으로 배치해 주세요. 발표 시간, 팀원 이름, 역할 분담은 제공된 정보가 있을 때 반영해 주세요. 각 본문 슬라이드에는 발표자가 말할 핵심 포인트를 발표자 노트로 2~3문장 적어 주세요.

## 프로젝트 소개

JobBridge는 구직자가 채용공고에 직접 지원하거나 관리자에게 취업연계를 신청할 수 있는 웹 서비스입니다. 기업은 공고를 등록하고 지원자와 면접을 관리합니다. 관리자는 기업 가입과 공고 게시를 심사하고, 취업연계 신청자를 기업에 추천합니다.

발표에서는 직접 지원과 관리자 추천의 차이를 보여 주세요. 직접 지원은 구직자가 공고를 선택하고 이력서를 제출하면서 시작합니다. 취업연계는 구직자의 신청을 관리자가 접수한 뒤 기업에 후보를 추천하면서 진행합니다. 기업은 추천을 검토해 회신하고 면접 일정을 제안할 수 있으며, 구직자는 수락·변경 요청·거절로 응답할 수 있습니다.

## 본문 슬라이드 구성

| 순서 | 슬라이드 | 담을 내용 |
|---|---|---|
| 1 | 표지 | JobBridge와 한 줄 소개. 팀명·발표자 정보가 있으면 추가 |
| 2 | 개발 배경과 목표 | 공고 검색에서 지원 상태와 면접 일정 확인까지 이어지는 과정, 관리자 추천이 필요한 경우를 함께 설명 |
| 3 | 역할별 기능 | 구직자는 탐색·지원·연계 신청, 기업은 공고 등록·지원자 검토·면접 관리, 관리자는 기업·공고 심사와 추천 |
| 4 | 채용공고 직접 지원 | 공고 선택, 이력서 제출, 기업의 검토와 구직자의 진행 상태 확인. 지원 기록이 공고·구직자·이력서를 연결한다는 점을 설명 |
| 5 | 관리자 주도 취업연계 | 연계 신청, 관리자 추천, 기업 회신, 면접 제안과 응답. 직접 지원과 다른 시작점과 담당자를 명확히 표시 |
| 6 | 기업과 공고 심사 | 기업 가입 심사와 개별 공고 게시 심사를 구분. 공고 작성·심사 대기·게시 흐름과 반려 시 사유 확인을 설명 |
| 7 | 시스템 구성 | React·Vite 화면, Java 17·Spring Boot REST API, Spring Data JPA와 DB의 역할을 간단한 흐름도로 설명 |
| 8 | 라이브 시연 | 기업 계정에서 공고 작성 및 심사 요청, 관리자 계정에서 게시 승인, 구직자 계정에서 공고 확인 및 이력서 제출. 마지막에 내 지원 내역에서 결과 확인 |
| 9 | 마무리 | 세 역할이 채용을 어떻게 이어가는지, 직접 지원과 관리자 추천이 각각 어떤 상황에 쓰이는지 짧게 정리 |

## DB 명세 부록

- 프로젝트 SQL의 CREATE TABLE 정의를 중복 제거하면 총 45개입니다. 기본 스키마에 39개, 광고 관련 SQL에 4개, 진로 검사·탐색 관련 업그레이드 SQL에 2개가 있습니다. 배포 DB의 실제 테이블 수는 별도 확인이 필요합니다.
- 전체 목록은 회원·인증, 프로필·콘텐츠, 채용·지원, 취업연계, 진로·평가·후기, 광고·홈 운영의 6개 영역으로 나눕니다. 각 행에 테이블명, 용도, PK, FK 참조 대상, 정의 파일을 표시합니다.
- 핵심 테이블은 별도의 상세 표로 설명합니다. 대상은 users, job_seekers, companies, job_postings, resumes, applications, interviews, employment_links, employment_referrals, employment_interview_proposals, employment_onboarding입니다. 컬럼명, 자료형, NULL 허용 여부, 기본값, PK/FK, 설명을 SQL과 대조합니다.
- 전체 45개의 컬럼 단위 명세가 필요하면 SQL로 확인한 범위에서 부록을 확장합니다. 긴 표는 글자를 줄이는 대신 여러 장으로 나눕니다. 업그레이드 SQL이 기본 정의를 변경하는 경우 적용 여부를 구분해서 표시합니다.
- 전체 목록과 상세 명세의 범위를 슬라이드에서 명시하고, 추정한 컬럼이나 제약 조건을 넣지 않습니다.

## 디자인 기준

- 16:9 화면, 흰 배경, 남색 제목, 청록색 강조를 기본으로 합니다. 표지부터 부록까지 같은 글꼴, 좌우 여백, 제목 위치를 적용합니다.
- 제목과 단계 번호를 과하게 키우지 않습니다. 본문은 보통 제목 28~32pt, 본문 17~20pt에서 시작해 실제 투사 화면에서 읽히는지 확인합니다.
- 사람 사진은 넣지 않습니다. 실제 서비스 화면이 제공되면 필요한 부분만 잘라 쓰고, 자료가 없다면 역할별 흐름도와 편집 가능한 표로 설명합니다.
- 단계형 슬라이드는 단계마다 담당자와 행동을 짧게 표시합니다. 모든 페이지에 같은 3열 배치를 반복하지 않고, 역할 비교·업무 흐름·기술 구성·명세에 맞춰 배치합니다.
- 실측하지 않은 성과 수치, 이용자 수, 배포 상태, 시연 성공 여부는 기재하지 않습니다.
